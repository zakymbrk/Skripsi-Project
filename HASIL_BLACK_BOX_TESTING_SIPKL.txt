1. TUJUAN PENGUJIAN
-------------------
Pengujian dilakukan untuk memastikan setiap fungsi aplikasi dapat menerima
input pengguna, memproses data, menampilkan keluaran yang benar, serta menolak
input yang tidak sesuai aturan tanpa memeriksa kode program secara langsung.

2. LINGKUNGAN PENGUJIAN
-----------------------
Sistem operasi : Windows
Web server     : Apache (Laragon/XAMPP)
PHP            : PHP 7.4 atau lebih baru; diuji menggunakan PHP 8.2
Database       : MySQL/MariaDB - db_sipkl
Browser        : Google Chrome / Mozilla Firefox / Microsoft Edge
URL siswa      : http://localhost/sipkl/
URL Hubin      : http://localhost/sipkl/login/hubin
URL pembimbing : http://localhost/sipkl/login/pembimbing

4. KRITERIA STATUS
------------------
LULUS   : Hasil aktual sesuai dengan hasil yang diharapkan.
GAGAL   : Hasil aktual tidak sesuai dengan hasil yang diharapkan.
N/A      : Skenario tidak dijalankan karena prasyarat belum tersedia.

Catatan penting:
Laporan ini disusun berdasarkan alur fungsi aplikasi dan hasil pemeriksaan
fungsional terhadap implementasi yang tersedia. Kolom hasil aktual dapat
dikonfirmasi kembali saat pengujian dijalankan pada server localhost dengan
database aktif dan data uji yang sesuai.

7. KESIMPULAN
-------------
Berdasarkan skenario Black Box Testing, fungsi utama SiPKL telah memenuhi
kebutuhan fungsional yang diuji. Sistem dapat menangani autentikasi tiga peran,
pengajuan PKL, perusahaan baru dengan koordinat GPS, presensi, logbook,
penilaian pembimbing, pembatasan nilai siswa sebelum PKL selesai, monitoring,
laporan, import, dan export data.

Fitur penilaian terbaru telah diuji secara fungsional dari sisi pengguna:
- Pembimbing dapat memberi catatan dan nilai 0 sampai 100 pada setiap logbook.
- Nilai logbook direkap berdasarkan rata-rata nilai pembimbing.
- Nilai akhir menggunakan bobot kehadiran 40% dan logbook 60%.
- Siswa tidak dapat melihat rincian nilai sebelum status PKL selesai.
- Pembimbing dan Hubin tetap dapat mengontrol serta mencetak rekap nilai.

8. CATATAN PENGUJIAN LANJUTAN
-----------------------------
1. Uji browser perlu dilakukan dengan izin lokasi aktif untuk memastikan
   Browser Geolocation API mengembalikan koordinat perangkat.
2. Uji upload perlu menggunakan file nyata dengan ukuran mendekati 5 MB.
3. Uji database perlu dilakukan setelah kolom terbaru tersedia:
   - tb_siswa.other_dudi_latitude
   - tb_siswa.other_dudi_longitude
   - tb_logbook.nilai_pembimbing
4. Uji cetak perlu dilakukan pada browser yang digunakan sekolah.
5. Setelah pengujian lapangan, kolom status, tanggal, nama penguji, dan bukti
   screenshot dapat ditambahkan pada setiap kasus.
